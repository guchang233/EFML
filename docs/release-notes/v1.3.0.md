EFML 1.3.0：直接启动（借用官方启动器身份）。

## 新功能

- **直接启动终末地**：新增 `EFML.Launcher.exe` 与管理器「直接启动游戏」按钮。它用本机正版、签名有效的官方 `Games.exe` 创建一个**暂停**进程作为游戏的直接父进程，再创建 `Endfield.exe`，因此不需要打开鹰角启动器界面。
  - 客户端 1.6.3 的启动校验（父进程名 + Authenticode 签名 + 证书指纹）不变；EFML 只提供符合校验的父进程，不修改游戏文件。
  - 直启需要一次管理员授权（UAC）；`Endfield.exe` 与官方启动器本身都要求管理员权限。
  - 找不到官方启动器、签名无效或启动器升级导致路径变化时，会明确报错，不会换用其他程序。
- **两条启动路径**：管理器保留「用官方启动器启动」；也可以照旧从鹰角启动器点「开始游戏」。两条路径都通过 `xinput1_4.dll` 代理加载模组。
- **官方启动器设置**：设置页新增官方启动器路径（留空自动查找）、签名者/版本展示和一键检查。
- **`efml launch --direct`**：安装代理（如需要）→ 预检官方启动器 → 请求 UAC → 启动游戏。`efml launch --check` 只打印会用的 game / home / parent / publisher，不启动、不提权。
- **`--home` 双开**：`efml launch --direct --home <dir>` 为该实例设置 `EFML_HOME`，两个实例各读自己的 `loader.ini` 与模组列表，不需要第二份启动器副本。
- **注入通道同步升级**：`EFML.Injector.exe` 默认也走同一父进程桥，并在游戏退出后清理借用的暂停父进程。用于不安装代理、只想注入启动的场景（命令行，高级）。

## 变化

- 运行时新增 `EFML.Launcher.exe`；`efml setup` 与管理器安装运行时会一并复制。运行时目录为 `runtime\1.3.0\`。
- `efml launch` 不带 `--direct` 时行为不变：只准备代理并提示从官方启动器开始。
- 官方启动器发现逻辑支持鹰角（CN）与 GRYPHLINE（国际）两个签名者；优先使用版本号最高的启动器目录。
- 直启桥代码来自 Better Endfield Next 4.1.4，并补上了其文档声称但实现中缺失的 Authenticode 校验。

## 升级

覆盖安装即可，设置与模组保留。升级后点一次「直接启动游戏」或运行 `efml launch --direct`，加载组件会更新到 1.3.0；已在运行的游戏不受影响。

## 验证范围

- 宿主 / 阶段 / 崩溃 / 启动器桥的自动化测试全部通过（桥测试覆盖参数解析、引用、非 PE 与未签名文件的拒绝、版本目录解析）。
- 本机 `efml launch --check` 能发现 `E:\Program Files\Hypergryph Launcher\1.6.0\Games.exe`，签名者显示为 `Shanghai Hypergryph Network Technology Co., Ltd.`。
- **首次真机直启尚未验收**：直启需要 UAC，自动化测试不启动游戏。成功判据：`%LOCALAPPDATA%\EFML\logs\loader.log` 出现 `Host loaded`，管理器「宿主 / 游戏线程 / 模组」变为运行中。

## 已知限制

- 直启依赖本机正版官方启动器文件；官方改动校验方式时可能失效，届时先看 `logs\loader.log` 的 `launcher:` 行。
- 每次直启弹一次 UAC；EFML 管理器不常驻管理员。
- 不能与 Better-Endfield 在同一游戏进程中同时使用；仅支持 Windows x64。
- 使用模组与直启可能违反游戏服务条款并导致账号受限，请自行评估；反作弊行为不受 EFML 控制。
