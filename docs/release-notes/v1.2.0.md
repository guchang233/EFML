EFML 1.2.0：崩溃记录和开发换版。

## 新功能

- **崩溃记录**：游戏出现内存访问错误、非法指令、栈溢出等异常时，EFML 会写入 `crash\crash.log`，包括：
  - 调用栈；
  - 出错时栈上有哪些模组；
  - 每个模组当时在做什么（模组通过新接口 `crash_mark` 标注）。

  已解析过的游戏方法直接显示方法名，不用再离线反查地址。游戏因此退出时会单独标为"游戏崩溃"。
- **管理器「崩溃记录」页**：用中文说明每条记录是什么异常、是否导致游戏退出、涉及哪个模组。调用栈默认折叠；"复制给 AI"可以一键复制结构化记录。
- **`efml crash`**：在命令行查看崩溃记录。`--json` 输出结构化数据，便于脚本和 AI 读取；`--all` 包括游戏可能已自行处理的异常。
- **`efml stage`（开发换版）**：
  - 复制模组包，把身份改为 `<原id>.dev<N>`，下次游戏启动时自动切换到最新开发版，不影响正在运行的游戏。
  - `--home` 可以重复，一次更新多套配置（例如房主和房客）。
  - `efml apply-staged` 可以在游戏关闭时立即切换。
- 在崩溃目录放一个空文件 `minidump.on`，或设置 `EFML_MINIDUMP=1`，致命崩溃时会写内存转储。

## 给模组作者

- `EFML/Module.h` 新增 `EFML_GetCrashMark`，用法见 [开发文档](https://github.com/guchang233/EFML/blob/main/docs/MODULE-API.md)。接口追加在扩展结构末尾，已有模组无需重新编译。
- 热重载的限制写进了文档：只有声明了 `prepare_shutdown`、且不持有托管对象的模组适合在游戏运行中换版，其他模组请用 `efml stage` 加重启游戏。

## 升级

覆盖安装即可，设置和模组保留。升级后在「启动」页点一次「启动游戏」，加载组件会更新到 1.2.0。

## 已知限制

- 崩溃记录、`efml stage` 和管理器崩溃页都通过了自动化测试（崩溃记录 27 项、宿主 36 项、换版 31 项），尚未在游戏内验证。
- 崩溃记录在异常发生的第一时间写入，其中一部分异常游戏会自行处理。管理器默认只显示导致游戏退出、或栈上有模组的记录。
- 不能与 Better-Endfield 在同一游戏进程中同时使用；仅支持 Windows x64。
- 使用模组可能违反游戏服务条款并导致账号受限，请自行评估风险。
